# 且记 Windows

Windows 版的独立工程，界面基线来自且记 Mac 0.2.6，在本目录单独维护，不引用或改写旁边 `macOS/` 的工程文件。两端同属一个源码仓库。

[返回项目介绍](../README.md)

当前提供完整窗口、纸边收展、垂直拖动和托盘入口，以及新增与编辑、分组与排序、完成、回收站、JSON 导入导出及可靠保存。系统提醒和打印尚未开放。导入文件中的提醒字段保留，但不会发送系统通知。

## 目录

| 目录 | 内容 |
| --- | --- |
| `Frontend/` | 本工程自己的 React 界面、样式和系统桥接 |
| `Resources/` | 本工程的运行资源、字体、第三方许可和生成脚本 |
| `src-tauri/` | Rust 原生窗口、数据保存、导入导出和开发配置 |
| `Scripts/` | 本工程的前端生成、自动化检查和合成任务检查 |

## 开发

需要 Node.js、Rust、Python 3。Windows 还需要 C++ 构建工具及 WebView2。依赖版本由 npm 和 Cargo 锁文件固定。在本目录执行：

```bash
npm ci
npm run dev
```

开发版使用 `com.luyaowo.qieji.dev`，正式版预留 `com.luyaowo.qieji`，本地数据和网页存储按标识隔离。正常开发请使用 `npm run dev`，不要直接运行使用正式配置的调试程序。

Mac 可以运行本工程的预览与通用测试。它是 Windows 工程的预览，不是 Windows 真机验收，也不会读取现有 Mac 且记的数据目录。

Mac 本机预览时，托盘图标位于顶部菜单栏；Windows 托盘位于任务栏通知区域。开发 Windows 版不要求在 Mac 安装虚拟机，Windows x64 编译与打包由云端工作流完成。

前端修改后执行 `npm run frontend`，再重启开发预览。当前不依赖前端开发服务器，也不提供热更新。

## 保存与恢复

原生工作区先读取成功，再显示 React 清单。原生 JSON 是启动时的数据来源，不使用网页缓存覆盖它。

任务与回收站一起写入 `workspace.json`，同时保留 `workspace-previous.json`。先写同目录临时文件并同步，再替换；写入失败时显示失败状态，取消退出，保留窗口内编辑。此时仍可以导出任务。

当前文件损坏时读取上一版；两份均无法读取时停止自动保存，保留原文件并显示重新读取入口，不生成示例任务覆盖数据。

## 纸边与托盘

首次打开使用完整窗口。选择“收起到侧边”后，窗口缩成屏幕右侧的窄纸边；点击展开，上下拖动调整高度，再选择“完整窗口”恢复普通窗口。两种形态共用同一个 WebView，保留草稿、滚动位置与清单。切换前提交当前文字编辑并保存，失败则保留当前窗口。

关闭按钮会保存后隐藏到托盘；左键点击托盘图标打开完整清单，右键菜单提供打开清单、显示纸边和退出。工具栏“退出”与托盘“退出且记”都保存后彻底退出。若托盘创建失败，关闭按钮恢复为保存后退出，避免程序隐藏后无法找到。

中文组合输入期间不切换窗口或退出，需先确认输入。导入导出或窗口切换正在进行时，暂不受理其他窗口操作。

窗口偏好独立保存为数据目录中的 `window-preferences.json`，包含上次可见形态、屏幕、纸边相对高度和完整窗口尺寸，不进入工作区导出。偏好损坏时回到完整窗口，不覆盖任务文件。屏幕缺失时回到主屏并限制在可见范围；纸边可见期间低频检查可用区域，参数未变化就不重新设置窗口，减少多余的位置恢复。

首版纸边采用紧贴实际窗口边界的实色纸面，不使用外扩透明阴影或桌面鼠标钩子。Windows 多屏、缩放、点击区域和睡眠恢复仍需实机验收。

导入先验证和预览，再确认、保存导入前备份并合并。相同 ID 保留当前版本；单次导入不超过 20,000 条或 20 MB。合并前检查工作区未发生变化，备份失败时取消导入。导出不包含尚未添加的新任务草稿。

Windows 正式数据位于 `%LOCALAPPDATA%\com.luyaowo.qieji\`；开发版位于对应的 `.dev` 目录。导入前备份位于数据目录的 `Backups/`。

## 检查

```bash
npm run frontend
npm run check
npm run check -- --native-smoke
```

检查覆盖前端同步、任务逻辑、原生文件保存、损坏恢复、备份、写入失败以及合成数据下的实际原生桥接。最后一条会打开临时窗口，自动完成添加、编辑、回收、恢复、导入导出、保存失败和重试检查。

原生桥接检查只在调试构建中启用，使用全新临时数据目录，不读取现有工作区。自动化检查中的文件选择和确认使用固定合成选项，系统对话框另做手动验收。检查结果明确区分当前系统和 Windows 运行环境。

## Windows 构建

在 Windows x64 环境运行：

```bash
npm run build
```

候选安装包输出到 `src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`。安装包只打包静态资源和程序，不打包用户数据。

## 云端构建

仓库的 [Windows build (no release)](../.github/workflows/windows-build.yml) 工作流在 Windows x64 环境运行前端、原生存储检查及 NSIS 打包。修改本工程并推送到 `main` 时触发，也可在 GitHub Actions 中手动运行。仅修改 Mac 工程不会触发这项构建。

流程只读取仓库，不创建标签或 Release，不自动安装，也不上传可下载的安装包。候选包只保存在临时构建环境，构建摘要记录文件名和 SHA-256；运行结束后不保留候选包。依赖与 Rust 构建缓存用于减少后续构建耗时，不包含安装包目录。

云端检查与打包成功不代表已完成 Windows 桌面交互或安装验收。

版本号 `0.1.0` 是独立开发工程版本，未作为公开发行版发布。
