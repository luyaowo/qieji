# 第二阶段验证记录

日期：2026-11-04。范围：Windows 纸边与托盘实现，以及 Apple 芯片 Mac 上的开发预览。Windows 桌面交互验收仍需可交互 Windows 11 x64 环境。

## 实现范围

- 完整窗口、侧边展开、纸边收起和隐藏到托盘共用同一个窗口、WebView 与工作区，不刷新页面切换形态。
- 切换或隐藏前提交编辑并确认保存，写入失败取消操作。退出仍走保存后退出路径。
- 关闭按钮在托盘可用时隐藏；托盘初始化失败时恢复为保存后退出，避免窗口消失后无入口。
- 首次启动完整窗口；窗口形态、屏幕、纸边相对高度、完整窗口位置和尺寸独立保存在窗口偏好文件。任务工作区格式保持版本 2。
- 纸边窗口只占可见纸面范围，使用实色背景，不增加透明阴影点击区或全局鼠标钩子。
- 纸边拖动按手势逻辑坐标与目标屏幕缩放换算为实际像素，取消时恢复原高度。屏幕配置未变化时不重新布局。
- 系统提醒、打印和开机启动未纳入本阶段。Mac 工程未修改，未运行 Mac 整套功能回归。

## 手动预览与修正

已在本机预览中查看完整窗口、窄纸边和展开清单；切换保留输入草稿。正常关闭后进程仍运行，再次启动恢复已有完整窗口，原有 7 条开发测试任务保留。检查产生的合成草稿已清空。

拖动检查发现：自动化工具的移动事件没有携带鼠标按下状态，手势因此取消，但旧点击抑制计时器可能让后到的点击展开清单。已改为按手势生命周期抑制点击，并保留键盘点击和普通点击。

两条新增回归在原提交 `766ab54` 的界面源码上失败，修复后通过。自动化工具的取消路径不能当作真实鼠标拖动验收；原生桥接另外验证手势坐标、缩放换算、移动距离与取消恢复。

最终预览再次执行同一自动化取消手势，纸边保持收起；随后普通点击仍可正常展开。

还修正了原生窗口样式的设置顺序：底层 Mac 窗口库异步应用边框时会读取可缩放状态，因此先设置目标能力，再设置边框。原生检查确认切回完整窗口后恢复调整大小和最大化能力。
